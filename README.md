# Домашняя работа 11 Списки для задач

Telegram-бот на C# и .NET 8. Задачи можно группировать в именованные списки или оставлять без списка. Создание задачи состоит из ввода названия, даты и выбора списка. Список удаляется вместе с его задачами только после подтверждения.

## Запуск

Нужны .NET SDK 8.0 и доступ к NuGet при первом восстановлении пакетов. Используется Telegram.Bot 22.5.1. Команды выполняются в терминале из каталога решения ToDoBot.sln.

```powershell
dotnet restore --locked-mode
dotnet build -c Release --no-restore
$botKey = Read-Host 'Токен от BotFather' -AsSecureString
$env:TELEGRAM_BOT_TOKEN = [System.Net.NetworkCredential]::new('', $botKey).Password
try {
    dotnet run --project TelegramBot -c Release --no-build
} finally {
    Remove-Item Env:TELEGRAM_BOT_TOKEN -ErrorAction SilentlyContinue
}
```

В Bash:

```bash
read -rs -p 'Токен от BotFather: ' TELEGRAM_BOT_TOKEN
echo
export TELEGRAM_BOT_TOKEN
dotnet run --project TelegramBot -c Release --no-build
unset TELEGRAM_BOT_TOKEN
```

Токен вводится при запуске и передаётся через окружение процесса. Вставлять его в Program.cs, настройки проекта или README не нужно. Если TELEGRAM_BOT_TOKEN не задана, приложение сообщает об этом и завершает работу. Ошибки запуска не выводят токен или адрес запроса с ним.

После сообщения о запуске откройте личный чат со своим ботом и отправьте /start. Остановка - Ctrl+C. Для ответов нужны включённые компьютер, приложение и доступ к api.telegram.org. При ограничениях провайдера нужен VPN для всех программ.

## Команды и кнопки

| Команда | Действие |
|---|---|
| /start | Регистрация; повторный запуск сохраняет идентификатор пользователя |
| /addtask | Название, срок dd.MM.yyyy, затем выбор списка кнопкой |
| /show | Списки пользователя и кнопки Добавить и Удалить |
| /report | Количество всех, активных и завершённых задач |
| /cancel | Отмена текущего сценария |
| /completetask id | Завершение своей задачи |
| /removetask id | Удаление своей задачи |
| /help | Справка |

Основная клавиатура содержит ровно /addtask, /show и /report. Во время сценария вместо неё доступна /cancel. Встроенные кнопки относятся к конкретному сообщению.

При /show доступны «📌Без списка», личные списки, «🆕Добавить» и «❌Удалить». Выбранный список показывает активные задачи; фильтр совпадает с учебной демонстрацией. Завершённые задачи учитываются в /report и также удаляются при подтверждённом удалении их списка.

Название списка содержит от 1 до 10 символов после удаления пробелов по краям. Уникальность проверяется у одного пользователя без учёта регистра: Work и work обозначают одно имя. У разных пользователей одинаковые названия допустимы.

В сценарии удаления нужно выбрать список, затем нажать «✅Да» или «❌Нет». Отказ и /cancel сохраняют список и задачи. Чужой идентификатор, устаревшая кнопка подтверждения или обычное сообщение yes не разрешают удаление.

## Хранение данных

Пользователи, списки и задачи сохраняются в JSON-файлах users.json, lists.json и tasks.json в каталоге data. Путь можно изменить переменной TELEGRAM_DATA_DIR. Файловые репозитории пользователей и списков используют один механизм сериализации и замены файла через временную копию. Повреждённый JSON вызывает ошибку и не перезаписывается пустыми данными.

После перезапуска сохраняются идентификаторы и связи задач со списками. Незавершённый диалог хранится в ConcurrentDictionary в памяти и после перезапуска начинается заново. Для одного каталога данных следует запускать один процесс бота. Одновременные обращения внутри процесса защищены; сообщения одного пользователя обрабатываются последовательно.

Каталог data, переменные окружения, журналы и результаты сборки не входят в репозиторий. Хранилище содержит пользовательские данные; в выдаче оно не заполнено.

## Структура

- Core/Entities - ToDoUser, ToDoItem, ToDoList и состояние задачи.
- TelegramBot/Repositories - IToDoListRepository, FileToDoListRepository, FileUserRepository и общий JsonFileStore.
- TelegramBot/Services - интерфейсы и сервисы пользователей, задач и списков.
- TelegramBot/Dto - CallbackDto и ToDoListCallbackDto.
- TelegramBot/Scenarios - контексты и сценарии AddTask, AddList, DeleteList.
- TelegramBot/UpdateHandler.cs - команды и CallbackQuery.
- TelegramBot.Tests - проверки диалогов, сообщений API и файловых хранилищ.

CallbackDto использует формат action, а ToDoListCallbackDto - action|id. Без списка идентификатор пустой: show|. В callback_data передаются действие и GUID, названия списков туда не записываются. Проверяется предел 64 байта UTF-8.

AddTaskScenario сохраняет имя и дату до выбора списка. Задача добавляется только после выбора допустимого списка или варианта «Без списка». DeleteListScenario использует шаги null, Approve и Delete. При подтверждении удаляются все задачи выбранного списка текущего пользователя, затем сам список.

## Проверка

```powershell
dotnet test -c Release
```

Автоматические тесты проверяют создание и отмену сценариев, неверные даты и названия, уникальность списков, callback DTO, фильтрацию по пользователю и списку, подтверждение и отказ, устаревшие кнопки, каскадное удаление, перезапуск файловых сервисов и параллельные операции. TelegramBotClient работает с локальным HTTP-транспортом: реальные запросы в Telegram в этих тестах не отправляются.

Для проверки в Telegram:

1. Отправьте /start и /show, нажмите Добавить, введите Work.
2. Выполните /addtask: введите название, затем ошибочную дату 31.02.2027. Повторите ввод с 28.02.2027 и выберите Work.
3. Через /show выберите Work и убедитесь, что задача отображается. В варианте «Без списка» её быть не должно.
4. Нажмите Удалить, выберите Work, затем Нет. Список и задача должны сохраниться.
5. Повторите удаление и выберите Да. Список и его задачи должны исчезнуть.
6. Проверьте /cancel на шагах создания. Перезапустите приложение и проверьте сохранённые данные.
